# Render MySQL TLS image

Build from the repository root with this dedicated context:

```sh
docker build --platform linux/amd64 \
  -t trackpro-render-mysql:tls-local \
  -f deploy/render/mysql/Dockerfile deploy/render/mysql
```

The base is the inspected official `mysql:8.4` image, pinned to its MySQL 8.4.11
digest. `/etc/my.cnf` includes `/etc/mysql/conf.d/`; the image adds only
`trackpro-tls.cnf` there. It inherits `ENTRYPOINT ["docker-entrypoint.sh"]` and
`CMD ["mysqld"]`. The official entrypoint starts as root and switches to the
`mysql` system user before starting the server.

The existing disk must supply these mysql-readable files:

- `/var/lib/mysql/trackpro-tls/mysql-ca.pem`
- `/var/lib/mysql/trackpro-tls/mysql-server.pem`
- `/var/lib/mysql/trackpro-tls/mysql-server.key`

No credentials or TLS material are copied or generated by this image. The build
context allows only the Dockerfile, ignore file, and option file. Certificate
renewal remains necessary; image persistence does not extend certificate validity.
Missing or invalid TLS files must be corrected on the disk before startup.

The inherited entrypoint recognizes an existing database under `/var/lib/mysql/mysql`
and skips initialization. This image is intended for that initialized disk only.
An uninitialized disk containing `trackpro-tls/` fails the official MySQL
nonempty-directory check during initialization. Do not use this image to provision
a fresh disk. No custom initialization scripts or migrations are added.

## Proposed existing Render Private Service settings

These are proposed settings for a separately authorized deployment. Publishing
this source to GitHub does not authorize a Render change or deployment.

1. Switch the **existing** Private Service to GitHub-backed Docker source using
   repository `wariza818189/3a-trackpro-system` and branch
   `deploy/render-trackpro-demo`. Set **Runtime/Language** to **Docker**,
   **Root Directory** blank, **Dockerfile Path** to
   `deploy/render/mysql/Dockerfile`, and **Docker Build Context Directory** to
   `deploy/render/mysql`. Keep **Auto-Deploy** off for a supervised deployment.
2. Clear **Docker Command** completely. Do not replace the entrypoint or supply
   `mysqld` arguments: the inherited CMD and included option file handle startup.
3. Leave **Pre-Deploy Command** blank. Retain the same existing 5 GB disk mounted
   at `/var/lib/mysql`, existing service identity/internal hostname, private
   networking, region, instance count and environment credentials.
4. Keep the staged certificates at the three paths above. No secret-file upload
   or password rotation is needed for this image change.

Do not recreate the service or disk. The ability to change this live service from
image-backed to GitHub-backed source in place has not been verified. If Render
does not offer that conversion while preserving the service and disk, stop and
resolve it separately. Do not substitute a new service or disk. No GHCR image
publication is part of this workflow. The Laravel Dockerfile and web service are
untouched.

Render documents Git-backed Docker builds and context exclusions at
<https://render.com/docs/docker>.
